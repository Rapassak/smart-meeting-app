# Smart Meeting Management System

โปรเจกต์วิชา System Analysis & Design — เวอร์ชันโค้ดจริง (Node.js + Express + SQLite)

คู่มือนี้เขียนสำหรับคนที่ลืม VS Code ไปเกือบหมดแล้ว อ่านตามลำดับได้เลย ไม่ต้องรู้อะไรมาก่อน

---

## 1. สิ่งที่ต้องติดตั้งก่อน (ทำครั้งเดียว)

### 1.1 ติดตั้ง Node.js
โปรแกรมนี้เขียนด้วยภาษา JavaScript ที่รันฝั่งเซิร์ฟเวอร์ด้วย **Node.js** ถ้าเครื่องยังไม่มีต้องโหลดก่อน:

1. ไปที่ https://nodejs.org
2. โหลดเวอร์ชัน **LTS** (ตัวที่แนะนำ ไม่ใช่ Current) แล้วติดตั้งตามปกติ (Next > Next > Install)
3. ตรวจสอบว่าติดตั้งสำเร็จ: เปิด Terminal (หรือ Command Prompt) แล้วพิมพ์

   ```
   node -v
   npm -v
   ```

   ถ้าขึ้นเลขเวอร์ชัน (เช่น `v20.11.0`) แปลว่าใช้ได้แล้ว

### 1.2 เปิดโฟลเดอร์โปรเจกต์ใน VS Code
1. แตกไฟล์ zip ที่ได้รับไปไว้ที่ไหนก็ได้ที่จำได้ (เช่นในโฟลเดอร์ `Project SAD`)
2. เปิดโปรแกรม VS Code
3. เมนู **File > Open Folder...** แล้วเลือกโฟลเดอร์ `smart-meeting-app` ที่แตกไฟล์ไว้

## 2. รันโปรเจกต์ครั้งแรก

1. ใน VS Code เปิด **Terminal ในตัว** ด้วยเมนู **Terminal > New Terminal** (หรือกด `` Ctrl+` ``)
2. จะเห็น terminal ขึ้นมาด้านล่าง แล้วพิมพ์คำสั่งนี้เพื่อติดตั้งไลบรารีที่โปรเจกต์ต้องใช้ (ทำครั้งแรกครั้งเดียว หรือทำใหม่ทุกครั้งที่ package.json เปลี่ยน):

   ```
   npm install
   ```

   รอสักครู่จนกว่าจะขึ้นบรรทัดแบบ `added XX packages in Xs` (จะมีโฟลเดอร์ `node_modules` เกิดขึ้นมาใหม่ — อันนี้ปกติ ไม่ต้องไปแก้ไขอะไรในนั้น) **อย่าเพิ่งกด Ctrl+C ระหว่างรัน ปล่อยให้รันจนจบ**

   > ถ้าขึ้น error สีแดงยาวๆ พูดถึง `node-gyp` / `Visual Studio` / `prebuild-install` — ดูหัวข้อ **"ปัญหาที่อาจเจอ"** ด้านล่างสุด

3. สั่งรันเซิร์ฟเวอร์:

   ```
   npm start
   ```

   ถ้าเห็นข้อความ `Smart Meeting server กำลังทำงานที่ http://localhost:3000` แปลว่าสำเร็จ

4. เปิดเบราว์เซอร์ (Chrome/Edge) แล้วไปที่ **http://localhost:3000** — จะเจอหน้า **เข้าสู่ระบบ** จริง (ไม่ใช่แค่เลือกบทบาทแล้ว)
   ข้อมูลทุกอย่างถูกเก็บอยู่ในไฟล์ฐานข้อมูล `smart_meeting.db` แล้ว **ปิดเว็บ/ปิดเซิร์ฟเวอร์ไปข้อมูลก็ไม่หาย** เปิดใหม่มาก็ยังอยู่เหมือนเดิม

   ทดสอบเข้าใช้งานได้ทันทีด้วยบัญชีตัวอย่างที่มีให้แล้ว (รหัสผ่านเดียวกันหมด `demo1234`):

   | ชื่อผู้ใช้ | บทบาท |
   |---|---|
   | `employee1` | พนักงาน |
   | `organizer1` | ผู้จัดประชุม |
   | `admin1` | แอดมิน |

   หรือจะกด **"สมัครสมาชิก"** เพื่อสร้างบัญชีของตัวเองก็ได้ — ตอนสมัครจะให้เลือกบทบาทครั้งเดียว ระบบจะจำไว้ในฐานข้อมูลถาวร ครั้งต่อไปแค่พิมพ์ username/password เข้าสู่ระบบเฉยๆ ไม่ต้องเลือกบทบาทซ้ำอีก (และปิดแท็บ/ปิดเบราว์เซอร์ไปก็ยังจำว่า login ค้างอยู่ ไม่ต้อง login ใหม่ทุกครั้ง จนกว่าจะกด "ออกจากระบบ")

5. เวลาจะหยุดเซิร์ฟเวอร์ ให้กลับไปที่ terminal แล้วกด `Ctrl + C`

> **อัปเดตจากตอนติดตั้งครั้งแรก (ถ้าเคยรัน `npm start` ไปแล้วก่อนได้ระบบ login ตัวนี้):**
> โครงสร้างตาราง `users` เปลี่ยนไป (เพิ่ม username/password จริง) ตัวโปรแกรมจะ**ลบข้อมูลบัญชีเดิม (แบบเลือกบทบาทเฉยๆ) แล้วสร้างบัญชีตัวอย่างใหม่ให้อัตโนมัติ**ตอนรัน `npm start` ครั้งถัดไป ไม่ต้องลบไฟล์ `smart_meeting.db` เอง — ข้อมูลการประชุม/ห้อง/การจองเดิมยังอยู่ครบ กระทบแค่ตารางผู้ใช้เท่านั้น

> ทดสอบเปิดในมือถือได้ด้วย: ถ้าคอมกับมือถืออยู่ WiFi เดียวกัน หาเลข IP ของคอม (เช่น `192.168.1.23`) แล้วเปิด `http://192.168.1.23:3000` จากมือถือ หน้าเว็บจะปรับขนาดให้พอดีจอเองอัตโนมัติ

## 3. โครงสร้างไฟล์ (ไว้ดูตอนจะแก้โค้ด)

```
smart-meeting-app/
├── package.json          ← รายชื่อไลบรารีที่ใช้ + คำสั่ง npm start
├── smart_meeting.db      ← ไฟล์ฐานข้อมูล SQLite ตอนรันในเครื่องตัวเอง (เกิดขึ้นอัตโนมัติตอนรันครั้งแรก)
├── server/               ← โค้ดฝั่ง "หลังบ้าน" (backend)
│   ├── index.js          ← จุดเริ่มต้นของเซิร์ฟเวอร์ ต่อ route ต่างๆ เข้าด้วยกัน
│   ├── db.js             ← สร้างตารางฐานข้อมูล + ข้อมูลตัวอย่างเริ่มต้น (เลือก driver ด้านล่างอัตโนมัติ)
│   ├── db-drivers/
│   │   ├── local-sqlite.js   → ใช้ตอนรันในเครื่องตัวเอง (node:sqlite ที่ติดมากับ Node.js ไม่ต้อง compile)
│   │   └── turso-driver.js   → ใช้ตอน deploy ขึ้นเว็บจริง เชื่อมกับฐานข้อมูลคลาวด์ Turso (ข้อมูลอยู่ถาวร)
│   ├── util/
│   │   ├── password.js       → เข้ารหัสรหัสผ่าน (hash) + สร้าง session token
│   │   ├── session.js        → เช็คว่า request ที่เข้ามา "login อยู่หรือเปล่า เป็นใคร"
│   │   └── async-handler.js  → กันไม่ให้ request ค้างถ้าเกิด error ระหว่างคุยกับฐานข้อมูล
│   └── routes/           ← แต่ละไฟล์ = API หนึ่งกลุ่ม (จองห้อง, ประชุม, เช็คอิน, ...)
│       ├── auth.js           → สมัครสมาชิก / เข้าสู่ระบบ / ออกจากระบบ (ของจริง มี username+password)
│       ├── rooms.js          → ข้อมูลห้องประชุม + สถานะว่าง/ไม่ว่าง
│       ├── meetings.js       → สร้าง/แก้ไข/ยกเลิก/ดูรายละเอียดการประชุม
│       ├── bookings.js       → อนุมัติ/ปฏิเสธคำขอจองห้อง (สำหรับแอดมิน)
│       ├── checkin.js        → เช็คอินเข้าประชุม (จำลอง QR)
│       ├── notifications.js  → รายการแจ้งเตือน
│       └── dashboard.js      → สรุปผลภาพรวมสำหรับแอดมิน
└── public/
    └── index.html        ← โค้ดฝั่ง "หน้าบ้าน" (frontend) ทั้งหมด — HTML + CSS + JavaScript ในไฟล์เดียว
```

**เรื่อง login ที่ควรรู้**: รหัสผ่านไม่ได้เก็บเป็นตัวหนังสือธรรมดาในฐานข้อมูล แต่ถูก "แฮช" ไว้ (แปลงเป็นรหัสที่ถอดกลับไม่ได้) ด้วย `crypto.scrypt` ที่ติดมากับ Node.js เอง เวลา login สำเร็จเซิร์ฟเวอร์จะสร้าง "token" (รหัสลับสุ่ม) ส่งกลับไปให้ ฝั่งเว็บเก็บ token นี้ไว้ใน `localStorage` ของเบราว์เซอร์ แล้วแนบไปกับทุก request เพื่อบอกว่ากำลังใช้งานในนามใคร — วิธีนี้เรียกว่า **token-based session** เป็นวิธีมาตรฐานที่เว็บทั่วไปใช้กัน (แบบง่ายกว่า production จริงอยู่บ้าง เช่น token ไม่มีวันหมดอายุจนกว่าจะกด "ออกจากระบบ" — เหมาะกับ scope งานเดโม/วิชาเรียน)

**เรื่องฐานข้อมูลที่ควรรู้**: โปรเจกต์นี้เลือกใช้ฐานข้อมูล **2 แบบสลับกันอัตโนมัติ** โดยดูจากว่ามีการตั้งค่า environment variable ชื่อ `TURSO_DATABASE_URL` ไว้หรือเปล่า — โค้ดใน `server/routes/` ทุกไฟล์ไม่ต้องรู้เลยว่ากำลังใช้แบบไหนอยู่ เพราะหน้าตาการเรียกใช้งานเหมือนกันทุกประการ:
- **ไม่ได้ตั้งค่าไว้** (ปกติตอนรันในเครื่องตัวเองตาม 2 ข้างบน) → ใช้ไฟล์ `smart_meeting.db` บนเครื่อง ไม่ต้องสมัครอะไรเลย
- **ตั้งค่าไว้** (ตอน deploy ขึ้นเว็บจริงตามหัวข้อ 7 ด้านล่าง) → ใช้ฐานข้อมูลคลาวด์ **Turso** แทน ข้อมูลจะอยู่ถาวรแม้เว็บจะ sleep/redeploy ใหม่ก็ตาม

**หลักการทำงานคร่าวๆ**: `public/index.html` (ที่เบราว์เซอร์แสดงผล) จะยิง request ไปหา `server/` ผ่าน URL ที่ขึ้นต้นด้วย `/api/...` เช่น `/api/meetings` แล้ว `server/` จะไปอ่าน/เขียนข้อมูลในฐานข้อมูล (ไฟล์ `smart_meeting.db` ตอนรันในเครื่อง หรือ Turso ตอน deploy ขึ้นเว็บ — ดูหัวข้อ 6) แล้วส่งผลลัพธ์กลับมาเป็น JSON ให้หน้าเว็บเอาไปแสดง

## 4. อยากแก้โค้ดต่อ ต้องแก้ที่ไหน

| อยากแก้... | ไปแก้ไฟล์ |
|---|---|
| หน้าตา, สี, ฟอนต์, ปุ่ม, ข้อความในหน้าเว็บ | `public/index.html` (ส่วน `<style>`) |
| พฤติกรรมตอนกดปุ่ม / เปลี่ยนหน้า | `public/index.html` (ส่วน `<script>`) |
| กติกา/ตรรกะฝั่งเซิร์ฟเวอร์ (เช่น เงื่อนไขการอนุมัติห้อง) | ไฟล์ที่เกี่ยวข้องใน `server/routes/` |
| โครงสร้างตาราง หรือข้อมูลตัวอย่างเริ่มต้น | `server/db.js` (ถ้าแก้โครงสร้างตาราง ต้องลบไฟล์ `smart_meeting.db` ทิ้งแล้วรัน `npm start` ใหม่ เพื่อให้สร้างตารางใหม่ตามที่แก้) |

**ทุกครั้งที่แก้ไฟล์ใน `server/`** ต้องปิดเซิร์ฟเวอร์ (`Ctrl+C`) แล้ว `npm start` ใหม่ การเปลี่ยนแปลงถึงจะมีผล
(หรือใช้ `npm run dev` แทน `npm start` — โหมดนี้จะรีสตาร์ทเซิร์ฟเวอร์ให้อัตโนมัติทุกครั้งที่บันทึกไฟล์)

**ไฟล์ `public/index.html`** แก้แล้วแค่กด **รีเฟรชหน้าเว็บ** (F5) ในเบราว์เซอร์ก็เห็นผลทันที ไม่ต้องรีสตาร์ทเซิร์ฟเวอร์

## 5. อยากดูข้อมูลในฐานข้อมูลตรงๆ

ถ้าอยากเปิดดูว่าในไฟล์ `smart_meeting.db` มีอะไรบ้าง แนะนำติดตั้ง extension **SQLite Viewer** ใน VS Code (ไปที่แถบ Extensions ด้านซ้าย ค้นหา "SQLite Viewer" แล้วกด Install) จากนั้นคลิกไฟล์ `smart_meeting.db` ก็จะเปิดดูตารางข้อมูลได้เลยโดยไม่ต้องเขียนคำสั่งอะไรเพิ่ม

## 6. Deploy ขึ้นเว็บให้เปิดได้จากทุกที่ (ไม่ใช่แค่ในเครื่องตัวเอง)

ตอนนี้เว็บเปิดได้แค่ตอนที่เครื่องเรารันเซิร์ฟเวอร์ค้างไว้ (`npm start`) และเปิดได้แค่ในเครื่องเดียวกัน หรือมือถือที่ต่อ WiFi เดียวกันเท่านั้น ถ้าอยากให้เพื่อนหรืออาจารย์เปิดดูได้จากที่ไหนก็ได้ (คนละบ้าน, ใช้เน็ตมือถือ) ต้องเอาโค้ดไป **deploy** (ฝากรันไว้บนเซิร์ฟเวอร์ของคนอื่นที่เปิดทิ้งไว้ตลอด 24 ชม.)

หัวข้อนี้ใช้ 2 บริการฟรี ทั้งคู่ไม่ต้องผูกบัตรเครดิต:

- **[Turso](https://turso.tech)** — ฐานข้อมูลบนคลาวด์ (ใช้ SQL แบบเดียวกับ SQLite ทุกอย่าง) เก็บข้อมูล `users` / `meetings` / ... ของเราไว้ถาวร
- **[Render](https://render.com)** — เอาไว้รันโค้ด Node.js ของเราจริงๆ 24 ชม. โดยเชื่อมตรงจาก GitHub

> **ทำไมต้องแยกเป็น 2 บริการ ทำไมไม่เก็บไฟล์ `smart_meeting.db` ไว้บนเซิร์ฟเวอร์เดียวกันเลย?**
> เพราะ hosting ฟรีอย่าง Render (และเจ้าอื่นๆ ส่วนใหญ่) มี "พื้นที่เก็บไฟล์ชั่วคราว" (ephemeral filesystem) — ไฟล์ที่เกิดขึ้นตอนรัน เช่นไฟล์ `smart_meeting.db` **จะหายไปทุกครั้ง**ที่ deploy โค้ดใหม่ หรือเว็บ "sleep" แล้วตื่นขึ้นมา (แผนฟรีของ Render จะ sleep เองถ้าไม่มีคนเข้าเว็บเกิน 15 นาที แล้วตื่นขึ้นมาใหม่ตอนมีคนเข้าอีกครั้ง ใช้เวลาประมาณ 1 นาที) ถ้าเก็บฐานข้อมูลไว้เป็นไฟล์บนเครื่องเดียวกับเซิร์ฟเวอร์ ข้อมูลผู้ใช้/การประชุมที่สร้างไว้จะหายทุกครั้งที่เว็บ sleep — จึงต้องแยกฐานข้อมูลออกไปอยู่ที่ Turso ซึ่งเก็บถาวรแยกต่างหาก ไม่เกี่ยวกับว่าเว็บ sleep หรือ deploy ใหม่กี่ครั้งก็ตาม

### 6.1 เอาโค้ดขึ้น GitHub ก่อน

Render ต้องดึงโค้ดจาก GitHub (อัปโหลดไฟล์ตรงๆ ไม่ได้) ถ้ายังไม่เคยใช้ GitHub:

1. สมัครบัญชีที่ https://github.com (ฟรี)
2. ที่หน้าแรกกด **"New repository"** ตั้งชื่อ เช่น `smart-meeting-app` เลือก **Private** ก็ได้ (ไม่บังคับเป็น Public) แล้วกด **Create repository**
3. วิธีอัปโหลดโค้ดที่ง่ายที่สุดสำหรับมือใหม่: ใน VS Code กดไอคอน **Source Control** (รูปกิ่งไม้ที่แถบซ้าย) แล้วกด **"Publish to GitHub"** เลือก repository ที่สร้างไว้ (หรือให้ VS Code สร้างให้เลยก็ได้) — VS Code จะจัดการ `git init` / `commit` / `push` ให้อัตโนมัติ
   > ถ้าไม่เห็นปุ่มนี้ ลองเมนู **View > Source Control** ก่อน แล้วกด "Initialize Repository" ตามด้วย "Publish to GitHub"
4. ทุกครั้งที่แก้โค้ดแล้วอยากอัปเดตเว็บที่ deploy ไว้ ให้กลับมาที่ Source Control พิมพ์ข้อความสั้นๆ อธิบายว่าแก้อะไร (commit message) กด **Commit** แล้วกด **Sync Changes** (Render จะ deploy โค้ดใหม่ให้อัตโนมัติ ดูหัวข้อ 6.4)

### 6.2 สมัคร Turso สร้างฐานข้อมูลคลาวด์

1. ไปที่ https://turso.tech กด **สมัคร/Sign up** (ใช้บัญชี GitHub ล็อกอินได้เลย ง่ายสุด)
2. เข้าหน้าจัดการฐานข้อมูล (dashboard ที่ https://app.turso.tech) แล้วมองหาปุ่มทำนอง **"Create Database"** / **"New Database"** ตั้งชื่ออะไรก็ได้ เช่น `smart-meeting-db` แล้วกดสร้าง
3. เมื่อสร้างเสร็จ เข้าไปในหน้ารายละเอียดฐานข้อมูลนั้น มองหาส่วนที่เกี่ยวกับ **"Connect"** หรือ **"Credentials"** จะมี 2 อย่างที่ต้องคัดลอกเก็บไว้:
   - **Database URL** — ขึ้นต้นด้วย `libsql://...`
   - **Auth Token** — เป็น token ยาวๆ (กดปุ่มสร้าง/generate token ถ้ายังไม่มี) **คัดลอกเก็บไว้ตอนนี้เลย** เพราะบางทีจะโชว์ให้เห็นแค่ครั้งเดียว
   > หน้าตาปุ่ม/เมนูของเว็บอาจมีปรับเปลี่ยนไปบ้างตามเวลา ถ้าหาไม่เจอให้ลองมองหาคำว่า "URL" กับ "Token" ในหน้าเดียวกัน ปกติจะอยู่ใกล้กัน

เก็บ 2 ค่านี้ไว้ก่อน (Database URL กับ Auth Token) จะใช้ในขั้นตอนถัดไป — **ห้ามแชร์ Auth Token ให้คนอื่นเห็น** เหมือนรหัสผ่าน ใครมี token นี้จะเข้าถึงข้อมูลในฐานข้อมูลเราได้เลย

### 6.3 Deploy บน Render

1. ไปที่ https://render.com สมัคร/ล็อกอินด้วยบัญชี GitHub เดียวกับที่ push โค้ดไว้ (จะได้เชื่อม repo ได้ง่าย)
2. ที่หน้า Dashboard กด **"New"** แล้วเลือก **"Web Service"**
3. เลือก repository `smart-meeting-app` ที่ push ไว้ในขั้นตอน 6.1 (ถ้าไม่เห็น ให้กด "Configure account" เพื่ออนุญาตให้ Render เข้าถึง repo นั้นก่อน)
4. ตั้งค่าตามนี้:
   - **Name**: ตั้งชื่ออะไรก็ได้ (จะกลายเป็นส่วนหนึ่งของ URL เว็บ เช่น `smart-meeting-app.onrender.com`)
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type / Plan**: เลือก **Free**
5. เลื่อนหาส่วน **"Environment Variables"** (หรือกด "Advanced" ก่อนถึงจะเห็น) แล้วเพิ่ม 2 ตัวจากขั้นตอน 6.2:

   | Key | Value |
   |---|---|
   | `TURSO_DATABASE_URL` | ค่า Database URL ที่คัดลอกไว้ (ขึ้นต้น `libsql://`) |
   | `TURSO_AUTH_TOKEN` | ค่า Auth Token ที่คัดลอกไว้ |

   > ขั้นตอนนี้สำคัญมาก — ถ้าลืมใส่ 2 ตัวนี้ แอปจะมองไม่เห็น `TURSO_DATABASE_URL` แล้วเผลอไปสร้างไฟล์ SQLite ในเครื่อง Render เอง (เหมือนตอนรันในเครื่องเรา) ซึ่งจะโดนลบทุกครั้งที่ sleep — ข้อมูลจะหายอยู่ดี
6. กด **"Create Web Service"** (หรือ "Deploy") รอสักครู่ (หน้าจอจะโชว์ log การติดตั้ง คล้าย `npm install` ที่เคยเห็นในเครื่องตัวเอง) จนขึ้นสถานะ **"Live"**
7. เมื่อ deploy เสร็จ Render จะให้ URL มา ในรูปแบบ `https://ชื่อที่ตั้ง.onrender.com` — เปิดจากอุปกรณ์ไหนก็ได้ ไม่ต้องอยู่ WiFi เดียวกันอีกต่อไป

**การเข้าใช้งานครั้งแรก**: เหมือนตอนรันในเครื่อง ระบบจะสร้างตารางและใส่บัญชีตัวอย่าง (`employee1` / `organizer1` / `admin1` รหัส `demo1234`) ให้อัตโนมัติในฐานข้อมูล Turso ตอนเปิดเว็บครั้งแรก

**เว็บโหลดช้าตอนเปิดครั้งแรก**: ถ้าไม่มีคนเข้าเว็บเกิน 15 นาที แผนฟรีของ Render จะ sleep ให้เอง พอมีคนเข้าอีกครั้งจะ "ตื่น" ขึ้นมาใหม่ ใช้เวลาประมาณ 1 นาที (หน้าเว็บจะค้าง/โหลดนานผิดปกติแค่ครั้งแรก) ครั้งต่อๆ ไปจะเร็วปกติจนกว่าจะไม่มีคนเข้าอีก 15 นาที วนแบบนี้ไปเรื่อยๆ — ข้อมูลไม่หายเพราะอยู่ที่ Turso แยกต่างหากแล้ว

### 6.4 แก้โค้ดแล้วอยากอัปเดตเว็บที่ deploy ไว้

ไม่ต้องเข้าไปตั้งค่าอะไรใหม่ที่ Render อีก แค่:
1. แก้โค้ดในเครื่องตามปกติ (ทดสอบด้วย `npm start` ในเครื่องตัวเองก่อนให้แน่ใจว่าใช้ได้)
2. ใน VS Code ไปที่ Source Control → Commit → Sync Changes (push ขึ้น GitHub)
3. Render จะเห็นว่าโค้ดใน GitHub เปลี่ยน แล้ว deploy เวอร์ชันใหม่ให้อัตโนมัติภายในไม่กี่นาที (ดูสถานะ/log ได้ที่หน้า Render)

## 7. ปัญหาที่อาจเจอ

- **"npm: command not found"** → ยังไม่ได้ติดตั้ง Node.js หรือติดตั้งแล้วต้องปิด-เปิด VS Code ใหม่
- **"port 3000 already in use"** → มีเซิร์ฟเวอร์ตัวเก่าที่ยังไม่ได้ปิดอยู่ (กด Ctrl+C ใน terminal เดิม หรือปิด terminal นั้นแล้วเปิดใหม่)
- **เข้า localhost:3000 แล้วหน้าขาว/error** → เช็คว่ายังไม่ได้ปิด terminal ที่รัน `npm start` อยู่ และดูข้อความ error ใน terminal ว่าบอกอะไร
- **แก้ `server/` แล้วไม่เห็นผล** → ต้องปิด (Ctrl+C) แล้ว `npm start` ใหม่เสมอ
- **`npm install` ขึ้น error สีแดงยาวๆ พูดถึง `node-gyp` / `gyp ERR!` / `Visual Studio` / `prebuild-install`** →
  โปรเจกต์เวอร์ชันปัจจุบันไม่ใช้ไลบรารีที่ต้อง compile แบบนี้แล้ว (ใช้ `node:sqlite` ที่ติดมากับ Node.js เอง
  ตอนรันในเครื่อง และใช้ `@libsql/client` ธรรมดา ไม่ compile อะไร ตอน deploy) ถ้ายังเจอ error นี้อยู่ แปลว่าไฟล์
  `package.json` / `server/db.js` / `server/db-drivers/` ที่ได้รับยังเป็นเวอร์ชันเก่า — ลบโฟลเดอร์ `node_modules`
  กับไฟล์ `package-lock.json` ทิ้ง (ถ้ามี) แล้วรัน `npm install` ใหม่อีกครั้ง
- **ตอนรันขึ้นบรรทัดสีเหลือง `ExperimentalWarning: SQLite is an experimental feature`** → ปกติ ไม่ใช่ error
  ใช้งานได้ตามปกติ (เป็นแค่คำเตือนว่าโมดูล SQLite ในตัว Node.js ยังอยู่ในช่วงทดลอง — ขึ้นเฉพาะตอนรันในเครื่อง
  ไม่ขึ้นตอน deploy บน Turso เพราะไม่ได้ใช้ `node:sqlite` แล้ว)
- **Deploy บน Render แล้วเข้าเว็บได้ แต่พอผ่านไปสักพัก (เว็บ sleep แล้วตื่น) ข้อมูลที่สร้างไว้หายหมด** →
  แปลว่ายังไม่ได้ตั้งค่า Environment Variable `TURSO_DATABASE_URL` / `TURSO_AUTH_TOKEN` ที่ Render (หรือใส่
  ค่าไม่ถูก) แอปเลยเผลอไปสร้างไฟล์ SQLite ในเครื่อง Render เอง ซึ่งเป็นพื้นที่ชั่วคราว — กลับไปดูหัวข้อ 6.3
  ข้อ 5 เช็คว่าใส่ครบทั้ง 2 ตัวและค่าไม่มีช่องว่างเกินมาหรือขาดไป แล้วกด **"Manual Deploy" → "Deploy latest commit"**
  ที่ Render ใหม่อีกครั้ง (ไม่ต้องสร้าง Web Service ใหม่)
- **Deploy บน Render แล้ว log ขึ้น error เกี่ยวกับ Turso เช่น `401` หรือเชื่อมต่อฐานข้อมูลไม่ได้** → ลองเช็คว่า
  คัดลอก Database URL กับ Auth Token จาก Turso มาไม่ผิด/ไม่ขาดตัวอักษร (โดยเฉพาะ token ที่ยาวมาก บางทีคัดลอก
  มาไม่ครบ) ถ้าไม่แน่ใจให้กลับไปที่ dashboard ของ Turso สร้าง token ใหม่แล้วอัปเดตค่าใน Environment Variables
  ที่ Render อีกครั้ง
